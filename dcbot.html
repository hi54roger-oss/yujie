01 / WHY

為什麼開始做阿喵醬？

我一開始只是想知道：「Discord 上的 Bot 到底是怎麼做出來的？」 從最基本的訊息回覆開始，我開始研究 Discord Bot 的運作方式， 再進一步接觸 C++、DPP 與 Discord API。 實作過程中不只是增加功能，也不斷遇到編譯、編碼、API 與邏輯問題， 讓我逐漸理解到，真正的程式開發是把一個想法拆成可以實作、測試與修改的系統。

PROJECT MINDSET

想法
我想做一個屬於自己的 Discord Bot。
實作
研究 C++、DPP、API 與事件處理。
除錯
從錯誤訊息與實際結果找問題。
擴充
讓 Bot 從指令工具變成小型平台。

02 / TECHNOLOGY

技術架構

不是只列出工具，而是把每項技術在專案中的角色拆開。

C++

負責指令處理、功能邏輯、遊戲邏輯、資料處理與伺服器功能，是阿喵醬的主要開發語言。

DPP / Discord API

利用 DPP（Discord++）串接 Discord API，實作 Slash Command、事件、Button 與 Embed 等互動。

網路與 ICMP

透過 Windows 的 ICMP 相關 API 進行節點延遲測試，讓 /ping 不只是測試 Bot 是否在線。

CMake

使用 CMake 管理 C++ 專案的建置與相依設定，並在開發過程中處理編譯與環境問題。

Windows API

使用 Windows 系統提供的網路相關 API，讓 C++ 程式可以進一步與作業系統功能互動。

AI / 自然語言互動

將 AI 互動視為阿喵醬的擴充方向，讓 Bot 不只執行固定指令，也能往自然語言互動發展。

08 / DEBUGGING

阿喵醬不是一開始就會的

真正讓我學到最多的，往往不是「成功執行」的那一刻，而是程式不能執行的時候。 我曾經遇到 CMake、DPP 設定、Bot 啟動、權限與 UTF-8 中文亂碼等問題。 透過一次次編譯、觀察錯誤訊息、修改設定與重新測試，我開始建立自己的除錯流程。

PROBLEM 01

中文變成亂碼

從字串編碼與 UTF-8 問題開始理解「程式看到的文字」和「人看到的文字」並不一定相同。

PROBLEM 02

CMake / Library 編譯問題

學習確認編譯器、函式庫、路徑與專案設定，而不是只看最後一行錯誤。

PROBLEM 03

功能增加後變得複雜

當功能越來越多，開始需要思考模組化、邏輯拆分與重構。
