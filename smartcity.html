FEATURED PROJECT / SMART CITY

智慧城市｜臺北交通策略研究

運用 C++、交通資料與演算法，從路段壅塞分析出發，探索可驗證、能比較利弊的城市交通改善策略。

C++ Traffic Data Graph Robust Minimax

01 / 研究動機

參加清華大學 AI 體驗營後，我接觸了 AI、LLM、AI Agent、Linux 與資訊安全等技術，也開始思考如何將人工智慧真正應用於生活中的問題。受到營隊啟發，我決定挑戰過去未曾嘗試的大型專案，因此開始使用 OpenAI Codex 作為 AI 輔助開發工具，以 C++ 實作「智慧城市——臺北市交通壅塞分析與改善策略系統」。在開發過程中，我不只是讓 AI 產生程式碼，而是親自規劃系統架構、研究交通資料來源、設計演算法，並透過測試與除錯逐步完善功能。這次經驗讓我從單純的演算法解題，跨出到整合真實資料、系統設計與 AI 輔助開發，也讓我理解大型軟體專案需要的不只是程式能力，更包含問題分析、驗證與持續改進。

PROBLEM

臺北尖峰交通

以臺北市下班時段的交通壅塞為研究情境，觀察路段流量、行車延遲與道路網路間的連動。

GOAL

不只偵測，更要提出策略

希望透過可計算的模型比較交通改善方案，分析效益、成本及對其他路段可能造成的影響。

02 / 資料與處理流程

以官方交通資料與可追溯的道路識別資訊作為研究方向；資料品質與對應正確性是關鍵。

01

交通 VD 資料

專案曾使用 taipei_vd.xml、taipei_vd_static.xml 等資料，研究 VDID / DeviceID 到 LinkID 的對應。

02

路段彙整

研究將偵測器與車道資訊彙整至道路 Link，避免單一偵測點被誤當成整段道路狀態。

03

壅塞排序

以 top_links.csv 作為分析與輸出資料之一，持續檢查資料來源、單位與排序合理性。

03 / C++ 系統架構

以資料模型、路網模型與交通模擬拆分功能，讓每一步都能獨立驗證。

C++

Road / Intersection / Graph

以道路、路口與圖結構描述道路網路，作為路段連接關係與後續路徑分析的基礎。

MODEL

TrafficState / Scenario

將交通狀態與不同情境分開建模，以利比較尖峰、道路限制等條件。

EVAL

評估函數

以旅行時間、排隊長度等指標研究方案優劣；評分必須能解釋，而不是任意給方案 A、B 分數。

04 / 策略搜尋

從單一方案的評估延伸到多步決策與不確定情境。

SEARCH

Minimax / Alpha-Beta

研究以多層策略搜尋比較決策，並利用剪枝降低搜尋成本；深度與分支數需要依實測調整。

ROBUST

Robust Minimax

把不同交通情境納入比較，避免方案只在單一假設下表現良好。

TRADE-OFF

策略利弊

關注局部改善是否將壅塞轉移到鄰近道路，以及對學校、醫院、公車站等重要節點的影響。

05 / 開發紀錄與驗證

把有紀錄的測試成果與尚待確認的完整系統能力分開呈現。

STEP 7-A

TrafficModel 測試

先前開發紀錄顯示測試 108/108 通過；這代表該階段測試通過，不等於整個臺北市交通模型已完成實地驗證。

STEP 7-B

Evaluation 測試

先前開發紀錄顯示測試 166/166 通過；評估函數曾採用固定參考值的正規化方式與多指標權重。
